NexusAI API Reference

A production-ready AI SaaS backend multi-model chat, conversation history, credit billing, API key management, and usage analytics. Base URL: https://api.nexusai.dev/api/v1

Get started View on GitHub

Base URL

https://api.nexusai.dev/api/v1

All endpoints are prefixed with this URL. Requests must include Authorization: Bearer <token> unless noted as public.

Quick start

1 Register an account
request
bash 
curl -X POST https://api.nexusai.dev/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Jane Dev",
    "email": "jane@example.com",
    "password": "SecurePass1"
  }'
2 Log in and get your access token
request
bash 
curl -X POST https://api.nexusai.dev/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jane@example.com",
    "password": "SecurePass1"
  }'
response
json 
{
  "success": true,
  "message": "Login successful",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
3 Send your first AI chat message
request
bash 
curl -X POST https://api.nexusai.dev/api/v1/ai/chat \
  -H "Authorization: Bearer <your_access_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-1.5-flash",
    "message": "Hello! What can you help me with?"
  }'

Authentication

NexusAI uses JWT access tokens (15-minute expiry) delivered in the response body, and refresh tokens (7-day expiry) stored as httpOnly cookies. Send the access token in every authenticated request:

header 
Authorization: Bearer <access_token>

You can also authenticate using API keys via the x-api-key header see the API Keys module.

Response format

All endpoints return a consistent JSON envelope:

shape 
{
  "success": true,
  "message": "Human-readable message",
  "data": null,
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 100,
    "totalPages": 5
  }
}

meta is only present on paginated list endpoints. data is null on error responses.
